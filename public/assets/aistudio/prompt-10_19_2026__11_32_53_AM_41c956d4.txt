# Product Requirements Document (PRD)

# Jobnexa — Local Worker-Employer Connection PWA

***

## 1\. Overview

**App Name:** Jobnexa

Jobnexa is a Progressive Web App (PWA) designed to bridge the gap between local workers and employers by creating a hyper-local, skill-based job marketplace. Workers can register their skills, availability, and preferred job types, while employers can post job requirements and browse or hire available workers in their geographic vicinity. The platform features a real-time availability dashboard that displays the count of available workers in a specific domain and area, automatically decrementing this count when a worker is successfully hired, ensuring employers always see accurate, up-to-date workforce availability data.

The primary target audience includes two distinct user groups: **local workers** (daily wage earners, skilled tradespeople, gig workers, freelancers, and semi-skilled laborers such as electricians, plumbers, carpenters, delivery personnel, domestic helpers, and construction workers) and **employers** (small business owners, contractors, households, and local enterprises) who need immediate or short-term local labor. The key problems Jobnexa solves are: the inefficiency of informal word-of-mouth hiring, the lack of visibility workers have into available opportunities, the absence of a transparent system for employers to gauge workforce supply in their area, and the friction involved in matching the right skill set to the right job requirement quickly and reliably.

## 2\. Essential Core Features

### 2.1 User Authentication & Role Selection

* Dual-role registration: users sign up either as a **Worker** or an **Employer**
* Email/password authentication and OTP-based phone number verification
* Profile type is locked upon registration to maintain data integrity
* Secure session management with JWT tokens via Supabase Auth

### 2.2 Worker Profile Management

* Workers can create and edit a detailed profile including:
    * Full name, profile photo, contact number
    * Primary skill category (e.g., Electrician, Plumber, Carpenter, Painter, Driver, Domestic Help, etc.)
    * Secondary skills (multi-select)
    * Years of experience
    * Preferred job type (full-time, part-time, daily wage, contract)
    * Current availability status (Available / Unavailable / Hired)
    * Location (city, area/neighborhood — auto-detected or manually entered)
    * Expected daily/hourly wage
    * Short bio or work description
    * Past work experience entries

### 2.3 Employer Profile Management

* Employers can create and edit a profile including:
    * Company/individual name, logo or photo
    * Business type or category
    * Contact information
    * Location (city, area)
    * Brief description of their business

### 2.4 Job Posting (Employer)

* Employers can post job listings with the following fields:
    * Job title
    * Required skill category
    * Job description and responsibilities
    * Location of work
    * Duration (one-time, daily, weekly, monthly)
    * Pay rate (daily/hourly/fixed)
    * Number of workers needed
    * Application deadline
    * Job status (Open / Closed / Filled)

### 2.5 Worker Discovery & Availability Dashboard

* A publicly visible (to employers) dashboard showing:
    * Total number of available workers per skill category in a selected area
    * Filter by city, locality/neighborhood, and skill domain
    * Real-time count that decrements when a worker's status changes to "Hired"
    * Visual representation using counters, cards, and color-coded availability indicators (high/medium/low)

### 2.6 Worker Search & Filtering (Employer)

* Employers can search workers by:
    * Skill category
    * Location (city + area)
    * Availability status
    * Experience level
    * Expected wage range
* Results display worker cards with key info, availability badge, and a "Hire / Contact" button

### 2.7 Job Search & Filtering (Worker)

* Workers can browse available job postings filtered by:
    * Job category/skill
    * Location
    * Pay range
    * Job type (full-time, part-time, daily)
* Workers can apply to job listings directly through the app

### 2.8 Hiring Workflow

* Employer selects a worker → sends a hire request
* Worker receives a notification and can Accept or Decline the request
* Upon acceptance:
    * Worker's status automatically changes to **Hired**
    * The available worker count for that skill in that area decrements by 1 in real-time
    * Job post's required count decrements if multiple workers were needed
* When work is completed:
    * Employer or worker can mark the job as **Completed**
    * Worker's status resets to **Available**
    * The availability count increments back accordingly

### 2.9 In-App Notifications

* Push notifications (via PWA Web Push API) for:
    * New hire requests received (worker)
    * Hire request accepted/declined (employer)
    * New job postings matching worker's skill/location
    * Job application status updates
    * System alerts and reminders

### 2.10 Rating & Review System

* After job completion, both parties can leave a rating (1–5 stars) and a text review
* Ratings are displayed on worker and employer profiles
* Average rating shown on worker cards and employer profile

### 2.11 Real-Time Availability Counter

* Supabase Realtime subscriptions power live updates to availability counts
* Counts are segmented by: Skill Category + City + Area/Neighborhood
* Displayed prominently on the employer's discovery dashboard
* Auto-updates without page refresh

### 2.12 Admin Panel (Basic)

* View all registered workers and employers
* Manage skill categories and locations
* Moderate flagged reviews
* View platform-wide statistics (total workers, total jobs posted, total hires completed)

## 3\. Tech Stack

### Front-End

* **Framework:** React (with functional components and hooks)
* **Styling:** Tailwind CSS
* **Build Tool:** Vite
* **PWA Configuration:** Vite PWA Plugin (`vite-plugin-pwa`) with service worker, web manifest, offline caching, and installable PWA support
* **State Management:** Zustand or React Context API
* **Form Management:** React Hook Form with Zod validation
* **Routing:** React Router v6

### Back-End

* **Platform:** Supabase
    * **Authentication:** Supabase Auth (email/password + phone OTP)
    * **Database:** Supabase PostgreSQL
        * Tables: `users`, `worker_profiles`, `employer_profiles`, `skills`, `locations`, `job_postings`, `hire_requests`, `reviews`, `availability_counts`
    * **Real-Time:** Supabase Realtime for live availability count updates and hire status changes
    * **Storage:** Supabase Storage for profile photos, resumes, and documents
    * **Edge Functions:** Supabase Edge Functions for server-side logic (availability count triggers, notification dispatching)
    * **Row Level Security (RLS):** Enforced on all tables for data privacy and role-based access

### AI Integration

* **Provider:** OpenAI GPT-4o
* **Use Cases:**
    * **Smart Job Description Generator:** Employers can auto-generate a job description by entering a few keywords; GPT-4o generates a complete, professional job posting
    * **Skill Matching Suggestions:** Suggest the most relevant skill categories to a worker based on their free-text bio input
    * **Worker Profile Enhancement:** GPT-4o helps workers improve their bio/description with one click
    * **Job Recommendation Engine Text Summary:** Provide a short AI-generated explanation of why a particular worker matches a job posting

### APIs & Integrations

* **Geolocation API:** Browser Geolocation API for auto-detecting user city/area
* **OpenAI GPT-4o API:** As described in AI Integration section
* **Web Push Notifications API:** Via PWA service workers for native-like push notifications
* **Google Maps / OpenStreetMap (Leaflet.js):** Optional map view showing workers clustered by area
* **Supabase Realtime WebSocket:** For live counter updates

### Technical Requirements

* **PWA Compliance:** Must meet all PWA criteria — offline support for key screens, installable on Android/iOS home screen, service worker with caching strategies
* **Responsive Design:** Mobile-first, optimized for screens 320px–768px
* **Database Triggers:** PostgreSQL triggers in Supabase to automatically update `availability_counts` table when `hire_requests` status changes
* **Performance:** Lazy loading of routes and images; skeleton loaders for async data

## 4\. Design Preferences

### Interface

The Jobnexa PWA should feature a clean, modern, and approachable mobile-first interface that balances professionalism with accessibility, using bold iconography, clear card-based layouts, and intuitive bottom navigation to ensure ease of use for workers who may have limited digital literacy.

### Color Palette

| Role | Color | Hex |
| ---- | ----- | --- |
| Primary | Deep Blue (trust, professionalism) | `#1A3C6E` |
| Secondary | Vibrant Orange (energy, action) | `#F97316` |
| Accent | Soft Teal (availability indicator - active) | `#0EA5E9` |
| Success | Green (hired, completed) | `#22C55E` |
| Warning | Amber (pending, low availability) | `#F59E0B` |
| Danger | Red (unavailable, declined) | `#EF4444` |
| Background | Light Gray | `#F8FAFC` |
| Surface/Card | White | `#FFFFFF` |
| Text Primary | Charcoal | `#1E293B` |
| Text Secondary | Slate Gray | `#64748B` |

### Typography

* **Headings:** `Inter` (Bold / Semi-Bold) — clean and modern, excellent readability on mobile
* **Body Text:** `Inter` (Regular / Medium) — consistent with heading family for visual harmony
* **Accent/Labels:** `Inter` (Medium, uppercase with letter-spacing) for category tags and status badges

### Additional Design Considerations

* **Card-Based UI:** Workers and job listings displayed as rounded cards with subtle shadows
* **Availability Badges:** Color-coded pill badges (Green = Available, Orange = Busy, Red = Hired/Unavailable)
* **Bottom Navigation Bar:** 5-tab bottom nav for primary navigation (PWA mobile behavior)
* **Skeleton Loaders:** Shown during data fetching for all list/card views
* **Iconography:** Lucide React icon library for consistent, lightweight icons
* **Micro-animations:** Framer Motion for subtle transitions (page entries, badge updates, count changes)
* **Dark Mode:** Optional toggle (CSS variables based with Tailwind dark mode)
* **Install Banner:** Custom PWA install prompt banner displayed on first visit

## 7\. User Flow

### Flow A: Worker Registration to First Job Application

```
Step 1: Worker opens Jobnexa PWA on mobile browser
Step 2: Splash screen loads → "Get Started" tapped
Step 3: Onboarding carousel viewed (or skipped)
Step 4: Taps "Sign Up" → Sign Up screen
Step 5: Selects "Worker" role toggle
Step 6: Fills name, email, phone, password → "Create Account"
Step 7: OTP screen → enters 6-digit OTP received on phone
Step 8: Profile Setup Step 1 — uploads photo, fills basic info → "Next"
Step 9: Profile Setup Step 2 — selects "Electrician" as primary skill, adds secondary skills,
        enters experience, expected wage, taps "AI Enhance Bio" → reviews AI bio → "Next"
Step 10: Profile Setup Step 3 — taps "Detect My Location" → city/area auto-filled → "Complete Setup"
Step 11: Redirected to Worker Dashboard
Step 12: Sees availability toggle — taps to set status to "Available"
Step 13: Sees Recommended Jobs section — scrolls and finds a relevant job card
Step 14: Taps job card → Job Detail screen
Step 15: Reviews job description, sees AI Match Score card ("95% match – your electrical skills fit this role")
Step 16: Taps "Apply Now" → confirmation toast "Application Sent!"
Step 17: Returns to dashboard → My Applications section shows new entry with "Pending" status
```

***

### Flow B: Employer Posting a Job and Hiring a Worker

```
Step 1: Employer opens Jobnexa PWA → logs in (existing account)
Step 2: Directed to Employer Dashboard
Step 3: Views Availability Stats Hero Card — selects "Plumber" skill, area "Koramangala" →
        counter shows "12 Available Plumbers"
Step 4: Taps orange FAB "+" → Post a Job screen
Step 5: Enters job title "Need Plumber for Bathroom Renovation"
Step 6: Selects Skill Category "Plumber", taps "Generate with AI"
        → GPT-4o generates a detailed job description → reviews and edits
Step 7: Sets workers needed = 1, pay = ₹1200/day, duration = "2 days", location = "Koramangala"
Step 8: Sets application deadline → taps "Preview Job Post" → satisfied → "Publish Job"
Step 9: Success toast → returns to Employer Dashboard — job appears in "My Active Job Posts"
Step 10: Goes to "Search Workers" tab → filters by "Plumber" + "Koramangala"
Step 11: Browses result list → finds a worker with 5★ rating → taps "View Profile"
Step 12: Reviews worker profile (skills, bio, reviews, wage expectation)
Step 13: Taps "Send Hire Request" → Hire Request screen
Step 14: Links request to the published job post, adds message, confirms wage → "Send Hire Request"
Step 15: Success — returns to dashboard with confirmation
```

***

### Flow C: Worker Receiving and Accepting a Hire Request

```
Step 1: Worker receives push notification: "New Hire Request from [Employer Name]"
Step 2: Taps notification → Hire Requests screen → "Pending" tab highlighted
Step 3: Sees hire request card — employer name, job title, proposed wage, start date
Step 4: Taps "View Details" → expanded view shows full job details and employer message
Step 5: Taps "Accept" button → confirmation bottom sheet "Are you sure you want to accept?"
Step 6: Taps "Confirm Accept"
Step 7: Worker status automatically changes from "Available" → "Hired"
Step 8: Worker Dashboard shows Active Job Card for the accepted job
Step 9: Availability counter for "Plumber – Koramangala" decrements from 12 → 11 (real-time)
Step 10: Employer receives push notification: "Your hire request was accepted by [Worker Name]"
```

***

### Flow D: Job Completion and Review

```
Step 1: Worker completes the plumbing work
Step 2: Worker opens Jobnexa → Dashboard → sees Active Job Card
Step 3: Taps "Mark as Completed"
Step 4: Confirmation modal → "Confirm Job Completion" → confirms
Step 5: Job moves to History, Worker status resets to "Available"
Step 6: Availability counter for "Plumber – Koramangala" increments back from 11 → 12
Step 7: Employer receives push notification: "Job marked as completed by [Worker Name]"
Step 8: "Leave a Review for [Worker Name]?" prompt appears on employer's dashboard
Step 9: Employer taps → Leave Review modal → selects 5 stars, types review text → "Submit"
Step 10: Worker receives notification of new review
Step 11: Worker is prompted to rate the employer → goes to Hire Requests → History → "Leave Review"
Step 12: Worker rates employer → both reviews saved to database
Step 13: Worker's profile star rating updates to reflect new review
```

***

### Flow E: Employer Browsing Real-Time Availability Dashboard

```
Step 1: Employer logs in → navigates to "Availability" tab (bottom nav)
Step 2: Availability Dashboard loads with default location (employer's registered area)
Step 3: Sees skill category grid — all domains with live worker counts
Step 4: Filters by city "Bangalore" and area "Indiranagar"
Step 5: Grid updates — shows "Electricians: 8", "Plumbers: 5", "Carpenters: 3", etc.
Step 6: Notices "Carpenters" count is low (red card) — decides to post a job quickly
Step 7: Taps "Carpenter" card → drill-down modal shows list of 3 available carpenters
Step 8: Reviews each carpenter profile inline
Step 9: Taps "View Profile" on preferred candidate → Worker Profile Detail screen
Step 10: Sends hire request directly from this screen
Step 11: Upon confirmation, Carpenter count decrements live: "Carpenters: 3 → 2"
```
